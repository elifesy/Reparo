Reparo — Hosting Guide

Reference sheet for customer conversations about where to host Reparo.

🚫 Traditional Web Hosts (GoDaddy Shared, Hostinger, Bluehost…)

These will not work for Reparo. They are built for PHP + WordPress, not Node.js applications.

Problem Why it blocks Reparo
No persistent process Reparo runs as node server.js — a long-lived process shared hosts don't allow.
No native compilation better-sqlite3 compiles C++ bindings at install. No shell access = no install.
No port binding Reparo binds to a port (e.g. 3000). Apache controls all ports on shared hosting.
Ephemeral filesystem No guarantee the SQLite file (/data/reparo.sqlite) survives a server restart.
No terminal / npm You can't run npm install or start the server. Only file uploads via FTP.

⚠️ GoDaddy VPS or Dedicated Server — Different Story

GoDaddy sells two very different products. The distinction matters:

Product Works? Why
GoDaddy Shared Hosting No Same problems as above — PHP/Apache environment, no Node.
GoDaddy VPS / Dedicated Yes It's a real Linux server. Install Node, PM2, run Reparo normally.
Rule of thumb: if the customer has shell (SSH) access and can run commands, it will work. If they only get a cPanel file manager, it won't.

✅ Platforms That Work Well

Platform Fit Notes
Fly.io Best fit Already configured in Reparo's deploy scripts. Persistent volumes, Docker-based, great SQLite support.
Railway Good Persistent volumes available, auto-detects Node, easy env vars. Minimal setup.
Render Good Persistent disks on paid plans. Free tier uses ephemeral disk — SQLite data lost on redeploy.
VPS (Hetzner / DigitalOcean / Linode) Full control ~$6/month. You manage Node, PM2, SSL (Caddy). Best for long-term stability. No platform lock-in.
DigitalOcean App Platform Moderate Needs a mounted volume for SQLite. Simpler if you ever switch to Postgres.

🚫 Platforms That Won't Work

Platform Reason
Heroku (free/eco tier) Ephemeral filesystem — SQLite data is wiped on every dyno restart or redeploy.
Vercel Serverless functions only — no persistent Express server, no file system.
Netlify Same as Vercel — JAMstack/serverless, not suited for a stateful Node + SQLite backend.

📋 What's Needed on Any Host

  • Persistent disk — must keep /data/reparo.sqlite across restarts and deploys.
  • Node.js runtime — v18+ recommended; better-sqlite3 must compile on the target OS.
  • Environment variables — NODE_ENV, JWT_SECRET, ALLOWED_ORIGINS (required in production for CORS), and optionally PORT. SMTP credentials are not env vars — they're configured in the admin Settings UI and stored in the database.
  • Shell / SSH access — needed to run npm install and start the server.
  • Docker (optional but recommended) — ensures native modules compile correctly for Linux.

💡 Bottom Line for Customers

If they want to keep it simple and managed → Fly.io or Railway (already configured, ~$5–10/month).

If they want full control and lowest cost → VPS on Hetzner or DigitalOcean (~$6/month, yours forever).

If a customer insists on GoDaddy: ask specifically if they have a VPS or Dedicated plan with SSH access. If it's shared hosting, it won't work and there's no workaround without rewriting the backend.
